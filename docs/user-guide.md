## 便携版使用步骤

1. 把 `BoothAtelier-x.y.z-portable.exe` 放到任意目录。
2. 把 `booth_cookies.txt` 放在 exe **同一目录**（见 [Cookie 获取](#cookie-获取)）。
3. 双击运行。**首次启动**会把程序文件解压到 exe 同级的 `app-cache\`（约 10-30 秒，仅此一次），然后自动同步 BOOTH 资料库并检查全部文件更新。之后每次启动直接运行，约 1-2 秒就绪。
4. 所有工作文件（数据库 `data/`、素材 `downloads/`、cookies）默认都在 **exe 同级目录**，整个文件夹拷走即可使用。下载根目录可在「设置」中改到任意盘。

> [!TIP]
> 便携模式下数据不依赖 `%APPDATA%`。程序文件缓存在 exe 同级 `app-cache\`，随文件夹一起拷贝即可在新机器上免二次解压。Electron 的运行时状态（日志 `data\electron\logs\main.log`、Chromium 缓存、单实例锁）也位于 `data\electron\`。运行 `BoothAtelier-x.y.z-portable.exe /purge` 只清除 `app-cache\`，数据不受影响。

## Cookie 获取

1. 在浏览器中安装可导出 cookies 的插件，例如 *[Get cookies.txt LOCALLY](https://github.com/kairi003/Get-cookies.txt-LOCALLY)*。
2. 登录 <https://accounts.booth.pm/library>。
3. 以 Netscape 格式导出 cookies，保存为程序目录下的 `booth_cookies.txt`。
4. Cookie 过期时程序会弹窗提示。重新导出并覆盖文件即可自动生效：程序检测到文件变化后会**自动重新检查登录状态**并恢复，无需任何点击。即使文件被删除，把 cookies 文件放回弹窗提示的路径，同样会被自动识别并恢复登录。

> [!WARNING]
> `booth_cookies.txt` 等同于你的登录凭证，已被加入 `.gitignore`。切勿提交到仓库或分享给他人。

> [!IMPORTANT]
> **登录态只存在于 Cookie 文件本身。** 所有 BOOTH 网络请求都在进程内存 session 中进行，关闭程序后系统层面不残留任何登录 cookie。因此，把 exe 拷到新目录、删除 Cookie 文件，登录态即刻消失，不会出现「程序放哪都能登录」的情况。
>
> 「设置 → Cookie 文件」的输入框显示当前生效路径（未指定时为默认查找结果，exe 同级优先）。**选择文件… / 恢复默认** 会立即生效并自动检测登录；手动修改路径后点「检测登录状态」（或按回车）即可应用。也可以直接指定任意位置的 Cookie 文件。

## 功能详解

### 库同步

自动抓取购买库与赠送库的全部商品（列表页加商品详情页），在本地建立索引，支持资源库展示、宣传图、商品描述与全文搜索。同步只更新元数据，不会下载素材文件。

抓库时缩略图、宣传图与描述插图会直接下载到商品的 `images/` 目录，资源库和详情页都读取本地文件，打开即显示。文字更新优先处理，图片在后台自动补齐，无需人工确认。

### 更新检查

通过 BOOTH deeplink 协议提取每个下载链接的文件指纹（ETag 与文件大小），粒度比 BOOTH 网页的商品级更新提示更细，能精确到单个链接。

检查方式有三种：

- 启动时全局自动检查（可关闭）
- 手动点击「检查全部更新」
- 在单个商品页点击「检查此商品全部链接」

检测到更新后，可以设置为自动下载（也可关闭）。启动时的库同步与文件检查是两个独立开关，还可以设置启动检查间隔：距离上次全局检查不足设定天数时跳过本次检查。

### 下载

优先使用 `DL with BOOTH Library Manager` 专用链接，直接获取卖家上传的原始文件（如 unitypackage），不做 zip 包装。可以逐个文件确认下载，也可以下载单个商品的全部文件，或一键下载全部。

任务走多并发队列，支持断点续传与原子落盘。仍在排队的文件点击「立即下载」可以直接开始，不占用并发额度，也不需要等待排队顺序。

### 更新与下载页

所有下载任务集中在一个页面，类似 qBittorrent 的任务列表：

- 表头可拖拽调宽，行为与 Windows 资源管理器一致（左侧固定、右侧整体平移），双击恢复默认宽度，宽度会被记住
- 支持六种状态筛选
- 行内进度，单行取消与重试
- 全局暂停与恢复，一键重试失败项

### 深链接

程序接管 BOOTH 当前使用的 `booth-library-manager://` 兼容协议。在 BOOTH 网页点击「DL with BOOTH Library Manager」后，程序会自动拉起并把窗口前置，解析链接后直接进入下载，不经过排队。

- 若该文件此前已下载且内容未变（指纹一致），深链会跳过重复下载并提示「已是最新」。
- 若作者更新了文件，则正常下载，旧版本照常归档到历史目录。
- 支持网页按钮与 `/deeplink` 端点两种 URL 形态。

程序的副本可以同时存在多份。启动时会检查网页下载按钮当前指向哪个程序（「设置 → 启动时检查深链注册」，默认开启）。若指向其他副本，会在应用内询问是否改为本程序；选择「不注册」会自动关闭该检查，之后可随时在设置中重新开启。深链的**接收**不受此开关影响。

### 代理

设置页提供三档：系统代理、自定义、直连。

- **系统代理**跟随 Windows 系统设置，行为与 Chrome 一致。
- **自定义**支持 `http://`、`socks5://` 与裸地址三种写法。选中「自定义」时会自动填入检测到的 Windows 系统代理，点「保存代理设置」后生效。
- 自定义地址留空并保存时，等同于「系统代理」；若系统代理未开启，则直连。
- 系统 / 直连切换即时生效，无需重启。yt-dlp 视频下载也会使用当前生效的代理。

### 描述与媒体

程序会抓取商品的完整描述 HTML（包括多段落与内嵌视频 iframe），详情页按网页端风格渲染。

描述中的 YouTube、NicoNico、Vimeo 视频可通过 yt-dlp 下载到商品的 `videos/` 目录，之后可在本地播放器中离线观看。未安装 yt-dlp 时，程序会给出安装提示。

图片会自动生成缩略图（4000px 压缩到 360px，体积约为原图的 1%）：画廊缩略图条加载缩略图，点开的大图加载原图。大图支持滚轮缩放、拖拽平移与双击复位。

### 历史备份

旧数据一律不删除。

- 素材文件更新时，旧文件会移动到 `{下载根}/{商品编号}/history/{日期}/`。同名覆盖与作者改名重传两种情况都会立即归档。
- 商品简介或宣传图变化时，会在 `snapshots/` 中保存一份日期快照。
- 详情页与历史页各有一个日期下拉框，可分别查看某天归档的文件和某天的说明快照。

### 商品详情页操作

详情页顶部有两个按钮：

- **🔄 检查当前商品页面更新**：只根据商品编号重新抓取该商品的 BOOTH 页面并更新元数据（简介、标签、图片等）。适用于所有商品，包括不在全局库同步范围内的免费商品。不会下载文件；有变化时会保存旧版本快照。
- **🗑 删除当前商品**（红色）：需要输入商品编号二次确认。会删除本地数据库中该商品的全部记录与数据目录，并取消该商品正在排队或下载中的素材。已下载的文件夹（`downloads/{商品编号}`）不会被销毁，而是整个移动到与程序 exe 同级的 `deleted/{商品编号}-{时间}/` 目录。如果商品仍在你的 BOOTH 库中，下次全局同步会重新同步回来。商品有视频正在下载时无法删除，请等待下载完成。

## 数据目录结构

```
{数据目录}/                        # 数据文件（便携版为 exe 同级 data/）
└── items/{商品编号}/
    ├── images/                    # 缩略图、宣传图、描述插图（本地化）
    ├── videos/                    # yt-dlp 下载的描述内嵌视频
    ├── snapshots/                 # 商品说明历史快照
    └── description.html           # 当前说明

{下载根目录}/                       # 仅存放素材文件（便携版为 exe 同级 downloads/）
└── {商品编号}/
    ├── current/                   # 当前版本文件
    └── history/{日期}/            # 历史版本（更新时旧文件移入此处）
```

数据库与图片缓存位于数据目录中，下载根目录可在设置中改到任意盘。

## 已知问题

### 首次启动时点击深链接，浏览器可能报错

只有**首次启动**需要把程序文件解压到 `app-cache\`（约 10-30 秒，仅此一次）。如果恰好在此期间点击 BOOTH 网页的「DL with BOOTH Library Manager」，浏览器等不到应用响应，可能会显示「应用打开异常」之类的错误页。

**下载本身是正常的**：程序启动完成后会继续处理这条链接并开始下载，浏览器的报错可以直接忽略。之后的启动（包括通过深链接拉起）约 1-2 秒就绪，不会再出现这一等待。
